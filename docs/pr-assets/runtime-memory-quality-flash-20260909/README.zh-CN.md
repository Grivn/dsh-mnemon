# Issue #203 自动记忆质量验收

[English](./README.md) | **简体中文**

**结论：未通过完整记忆质量验收。** 四会话可以持续工作，当前配置大部分能够记住和召回，所有已询问的正式纠正均回答正确；但自动维护出现了有损替换、模块归属丢失、陈旧文档和临时内容残留。这些已经足以复现 [issue #203](https://github.com/omdsh-dev/dsh-mnemon/issues/203) 所描述的部分“乱七八糟”，不能把容量修复通过解释为自动记忆质量全部通过。

本报告验收 [PR #212](https://github.com/omdsh-dev/dsh-mnemon/pull/212) 的生产代码 `fce3873e9669c9a9eefb902b76ca8d0ddbf68700`，日期为 2026-09-09。新增内容为实验、证据和文档，以下质量缺陷尚未修复。所有真实模型请求均限定 `deepseek-v4-flash`，返回中观察到的模型也只有 Flash；关闭思考，未使用 Pro。

## 实测结果

每组都有后端、前端、Android、运维四个并发开发会话，共享项目 Runtime。开发提示只要求完成配置工作，由模型自行决定记忆操作；真实默认生命周期执行空闲审阅。结束后关闭开发会话，使用没有历史和开发文件权限的新会话回答配置问题。

| 指标 | 单空间，12 轮 | 四空间，12 轮 | 四空间，24 轮 |
|---|---:|---:|---:|
| 开发回合 / 新召回会话 | 48 / 12 | 48 / 12 | 96 / 28 |
| 当前事实在全部记忆来源中的覆盖 | 35/36，97.2% | 36/36，100% | 80/80，100% |
| 新会话回答正确 | 34/36，94.4% | 36/36，100% | 74/80，92.5% |
| 正式纠正回答正确 | 4/4 | 4/4 | 8/8 |
| 旧值回答 / 跨模块错误回答 / 无依据猜值 | 0 / 0 / 0 | 0 / 0 / 0 | 0 / 0 / 0 |
| 保留的精确临时标记种类 | 0 | 1 | 3 |
| 仍写着旧值的基础配置文档 | 4 | 4 | 4 |
| 最终热记忆条目 / 项目文档 | 22 / 6 | 29 / 5 | 13 / 23 |
| 热记忆峰值 / 最终字节数 | 7,095 / 7,095 | 6,684 / 6,684 | 10,079 / 5,615 |
| 自动空闲审阅 / 模型请求 | 40 / 321 | 41 / 299 | 85 / 654 |
| 被拒绝的记忆工具调用 | 1 | 3 | 4 |
| 实验耗时 | 4 分 34 秒 | 4 分 9 秒 | 12 分 5 秒 |

三组共完成 192 个开发回合、52 个新召回会话、152 项回答和 166 次自动审阅。所有开发回合最后一次配置检查均通过。四空间短程组有两次“先测后改”的中途失败，随后修正；原始自动评分把它们计为 `development-workload-incomplete`，人工复核判定工作已完成，原始标记保留在证据中。提交的报告器已区分中途失败和最终未完成。

覆盖率按 Runtime、Documents 和冷记忆的完整内容检查，并不意味着每个来源都最新、每条记录都能独立理解、每个新会话都能找回。三个实验的 Vitest 执行均成功，三个原始 `automatedVerdict` 均为 `fail`。

## 关键证据

1. **维护模型把整条替换当成了局部修改。** 长程第 22 轮（记录 `wave=21`），原条目有 frontend 名称和 11 个字段。模型以其中一段作为 `old_text`，新 `content` 只保留尾部内容并补一个字段，导致模块名称及 7 个原字段从该条目消失。第 24 轮更新前端端口时，同样只提交端口和重试次数，删掉原条目中的 `timeout_ms=1800`。这是实际成功的替换调用和前后快照，不是从召回分数推测的损失。该 Action 的契约是[替换一个完整条目](../../../plugins/dsh-mnemon-source-runtime/src/source.ts)，Source 按提交内容执行；本次没有触发容量归档流程。详见 [observations.json](./observations.json) 的 `long-four.lossyReplacements`。
2. **“存着”与“会用”有差距。** 单空间的前端端口明明存在，新会话仍回答 unknown；运维交接通道则根本未记住，审阅回执却声称已经保存。长程六个 unknown 都属于前端：超时、缓存 TTL、队列、批量上限、退避时间、健康路径。这六项仍在文档中。新会话对其中几项只查询空冷记忆，没有继续检索文档；对保留天数、分区键和审计事件则使用文档检索成功。不能把全部 unknown 都解释为存储引擎丢数据。
3. **旧文档与当前记忆冲突。** 两组短程的四份基础文档仍把重试次数写为 3/5/7/9，而 Runtime 已纠正为 11/13/17/19。长程又更改端口，四份基础文档同时留下旧端口和旧重试次数。审阅器遵守[文档只创建、不改写的边界](../../../src/host/subagent.ts)，部分回执明确知道文档过时；后续创建补充文档使最终文档数增至 23。这说明还缺少有效的过期信息与纠正关联处理。
4. **禁止保存的例子仍被保存。** 四空间短程把 `TEMP_USER_android` 留在一条否定规则里。长程第 14 轮创建的前端文档写明 `NO_MEMORY_frontend`、`FAKE_CREDENTIAL_frontend` 是“不应持久化的调试产物”，但正文仍保留其原文；这两项来自第 11 轮明确禁止记忆写入的任务。它们没有被采纳为真实配置或真实凭据，仍构成无用内容残留。禁止写入的当轮及所有新召回回合均没有成功写入；这个指标没有捕获后续回合重新引入旧内容的问题。
5. **错误调用被保护层拒绝，但模型操作尚不稳定。** 八次错误包括旧的结果工具名、不存在的工具、缺少字段、无效分支名和删除不存在的条目。实验均继续完成，未观察到这些拒绝导致实际删除。单空间另有两个重复热事实；长程存在重复的后端端口、前端交接/重试和检查点，以及一条没有模块归属的热记录。完整 98 条最终记录均已逐条审阅，见 [final-memory.json](./final-memory.json)。

## 方法、门槛与限制

运行前固定的门槛为：当前事实覆盖和新会话召回均至少 90%；正式纠正必须全部答对；临时标记、旧值回答、跨模块错误回答、无依据猜值、禁止写入回合的成功写入、冷记忆完全重复和容量超限均为零。自动执行错误另计为失败；同时人工审阅全部最终内容和错误/未知回答。具体协议、初始脚本哈希和扩展理由见 [protocol.json](./protocol.json)，实际输入见 [workload.json](./workload.json)，逐轮指标和回答结果见 [results.json](./results.json)、[observations.json](./observations.json)。两轮校准试跑不计入正式成绩。

环境为 macOS arm64、Node v25.1.0、发布的 DSH 0.1.2-rc.1、Native CLI 0.2.7。使用真实 Flash API、DSH AgentLoop/会话/公开 fork provider、Mnemon 默认生命周期和独立 Source/Provider。开发工具实际读写临时 JSON 配置并校验全部已确定字段；它们模拟配置开发，不执行真实前端、后端或 Android 工程构建。所有事实、日志和凭据样例都是合成数据，运行于隔离临时目录。

默认 guided 召回、guided 写回及 10,240 字节上限不变；只把空闲防抖从生产 30 秒缩短到 5 秒，资格评分规则不变。每轮四个会话并发，随后等自动审阅结束。短程没有自然写满，因此预先扩展后再执行 24 轮；没有直接填充热记忆。长程自行合并使其仍未归档，不能以这组成绩评价冷空间分类。

这是一组有界模拟：一个 DSH 进程中的四会话、每条件一次正式运行，不能推断 Windows、多个独立进程、真人半天开发或普遍准确率。配置事实仍可从代码重新获取；新读者被刻意禁止读文件，用于隔离记忆效果。短程与长程也不能用作空间数量的因果对照。模型共请求 1,274 次，适配器报告输入 4,557,451 tokens、输出 292,774 tokens；不据此估算账单。

## 复现与后续修复方向

提供已授权的 `DEEPSEEK_API_KEY` 和 `MNEMON_NATIVE_TEST_CLI` 环境变量后运行；脚本不读取个人凭据文件：

```sh
MNEMON_RUN_FLASH_QUALITY=1 MNEMON_FLASH_QUALITY_REPORT=/tmp/mnemon-flash-quality.json pnpm exec vitest run tests/runtime-memory-flash-quality.spec.ts
MNEMON_RUN_FLASH_QUALITY=1 MNEMON_FLASH_QUALITY_WAVES=24 MNEMON_FLASH_QUALITY_REPORT=/tmp/mnemon-flash-quality-long.json pnpm exec vitest run tests/runtime-memory-flash-quality.spec.ts -t 'four preconfigured'
```

普通 CI 默认跳过真实 API 实验；执行完成后必须检查质量评分和保留内容。当前提交的报告器增加了全报告脱敏、动态版本/哈希记录和中途检查失败的正确分类；历史输出保留原始判定，工作负载和生产行为未为提高成绩而修改。

后续应优先处理整条替换时的字段与归属保留、禁止持久化内容在后续审阅中的过滤，以及基础文档与纠正文档的检索关系；同时减少常规配置工作产生的碎片文档。这些应通过 Strategy 编排、明确的 Source Action 契约和受限的文档纠正/过期信息协作完成。Core 和 Provider 继续保持模块职责，文档保护边界应保留。该验收提交没有实施这些后续修复。
